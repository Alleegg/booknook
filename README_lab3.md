1. Базы данных

- ORM — это технология, которая связывает объектно-ориентированный код приложения с реляционной базой данных, позволяя работать с таблицами как с объектами, а запросы формировать через методы языка программирования.
Преимущества: ускорение разработки за счёт отказа от ручного написания SQL, снижение вероятности ошибок и защита от SQL-инъекций, автоматическое приведение типов, независимость от конкретной СУБД, упрощение поддержки и рефакторинга.
Недостатки: дополнительная прослойка может снижать производительность при сложных запросах, ограниченная гибкость в нестандартных ситуациях, необходимость изучения самой ORM, иногда генерация неоптимальных запросов.

- Миграции — способ версионирования схемы базы данных, при котором изменения структуры (создание таблиц, добавление полей, изменение индексов) описываются в виде программного кода. Позволяет последовательно применять изменения или откатывать их, синхронизировать схему в команде и между средами, хранить историю изменений вместе с исходным кодом.

2. Авторизация

- Basic auth — простейший метод, при котором логин и пароль передаются в заголовке Authorization в кодировке base64 при каждом запросе. Сам по себе не обеспечивает шифрования, поэтому всегда должен использоваться поверх HTTPS. Из-за отсутствия механизма выхода и постоянной передачи учётных данных применяется редко, в основном для внутренних сервисов.

- Session auth — серверный механизм: после успешного входа создаётся сессия, клиенту передаётся идентификатор сессии (обычно в куках). Сервер хранит состояние сессии. Удобно для традиционных серверных приложений, позволяет централизованно управлять сессиями, но требует масштабирования хранилища сессий и создаёт трудности в распределённых системах.

- JWT auth — метод, использующий самодостаточный токен в формате JSON, подписанный сервером. Токен содержит информацию о пользователе и передаётся в заголовке Authorization. Позволяет серверу оставаться без состояния, упрощает горизонтальное масштабирование. Недостатки: сложность немедленной инвалидации токенов, больший размер по сравнению с идентификатором сессии, необходимость тщательного контроля времени жизни и безопасного хранения на клиенте.

- Идентификация, аутентификация, авторизация — три последовательных этапа контроля доступа.
Идентификация — установление личности (предъявление логина или email).
Аутентификация — проверка подлинности личности (ввод пароля, биометрия).
Авторизация — определение прав и разрешений уже аутентифицированного пользователя.

- Хэширование — необратимое криптографическое преобразование данных в строку фиксированной длины для безопасного хранения паролей. Современные алгоритмы (bcrypt, Argon2) добавляют соль — случайную строку, уникальную для каждого пароля, и поддерживают замедление вычисления через параметр сложности, делая атаки перебором и радужными таблицами неэффективными. Проверка происходит путём хэширования введённого значения и сравнения результатов.

3. Архитектура

- Разделение на бэкенд и фронтенд — независимое существование серверной части (бизнес-логика, хранение данных, безопасность) и клиентской (интерфейс, взаимодействие с пользователем). Преимущества: параллельная разработка, упрощение масштабирования, развёртывание в отдельных контейнерах, возможность использовать разные технологии для клиента и сервера, чёткое разделение ответственности. Фронтенд становится универсальным клиентом, бэкенд — чистым API для веба и мобильных приложений.

- SPA-фреймворки — архитектурный подход, при котором загружается единственная HTML-страница, а вся навигация происходит без перезагрузки через динамическую подмену содержимого.
Популярные фреймворки: React, Angular, Vue.js, Svelte.
Преимущества: отзывчивый интерфейс, приближенный к нативным приложениям, уменьшение нагрузки на сервер за счёт клиентского рендеринга, повторное использование компонентов.
Недостатки: низкая начальная скорость загрузки, сложности с SEO-индексацией, повышенный расход памяти на клиенте, зависимость от включённого JavaScript.

4. API

- REST API - архитектурный стиль построения веб-сервисов на принципах: единообразный интерфейс, разделение клиента и сервера, отсутствие состояния, кэшируемость, многоуровневая система. Ресурсы идентифицируются через URI, операции выражаются стандартными методами HTTP (GET, POST, PUT, DELETE). Ответы обычно в JSON или XML. Ценится за простоту, масштабируемость и удобство интеграции.

- Куки — небольшие фрагменты данных, которые сервер через Set-Cookie просит браузер сохранить, и браузер автоматически прикрепляет их к каждому последующему запросу к тому же домену. Используются для хранения идентификаторов сессий, токенов, пользовательских настроек. Атрибуты безопасности: HttpOnly (запрет доступа из JavaScript), Secure (только по HTTPS), SameSite (ограничение cross-site запросов) — важны для предотвращения XSS и CSRF атак.
